# USI・CSA と先読み

## 接続から終局まで

1. アダプターはエンジンを起動し、usi / usiok、オプション設定と準備を行う。エンジンの作業フォルダは実行ファイルの親フォルダ。
2. CSA サーバーへ接続し、プレイヤー名と対局条件・trip で LOGIN する。ゲーム情報を検証し、アプリモードでは AGREE の前に main にマッチングを確認する。自分の参加中プレイヤー同士の対局を強制切断する設定が有効なら対象接続を終了し、それ以外は AGREE して START を待つ。
3. 局面と残り時間を管理し、自分の手番に position / go を送る。エンジンの bestmove を CSA の着手に変換して送信する。
4. 終局時は探索を停止して応答を回収する。勝敗や引き分けが確定した場合は gameover を送る。最大手数以外の #CENSORED は引き分けにせずエンジンを終了し、連続参加なら新しいエンジンを起動する。

接続後の無通信対策として CSA 空行を30秒ごとに送る。ログイン応答と対局開始通知には30秒のタイムアウトがある。現在対応する CSA 時間単位は 1sec、時間遅延は 0。秒読みと加算の併用は未対応で、未対応の条件では開始しない。通信時の持ち時間の計算と CSA 棋譜の取り扱いは adapter/src/usi_agent.rs を確認する。

CSA の共通時間条件と `Time+`・`Time-` の個別条件を解釈し、先後の持ち時間と加算時間をそれぞれ USI へ送る。先後で異なる秒読みは USI の単一 byoyomi では表せないため、対局開始前に拒否する。開始局面の盤面が欠落・重複している場合や先後の玉が不足している場合も受諾しない。

開始局面に含まれる指し手は対局開始前の手順として扱い、開始時の持ち時間は Total_Time のままとする。手順に含まれる消費時間は履歴に保持するが、開始前の時計に加算・減算しない。途中再開時の残り時間は CSA の開始局面だけでは判別できない。

## 先読み

設定の ponder は初期状態で無効。有効なら USI 初期化時に USI_Ponder=true を送る。自分の指し手がサーバーから返った後、bestmove の予想手が合法なとき、その手を含む局面で go ponder を送る。

- 予想が当たれば ponderhit を送り、その探索を通常思考として継続する。
- 外れれば stop を送り、停止した探索の bestmove を捨ててから実局面で go する。
- 予想手がない・不正な場合は先読みせずに待つ。
- 先読み外れ・終局・切断時は探索停止と bestmove の回収を行う。stop 送信から10秒以内に応答が届かなければ、stop を重複送信せずエラー終了する。対局中の通信切断後はエンジンを再起動して次局に参加する。

読み筋を含む info は各行を analysis_update として通知し、depth、seldepth、time、評価値、Bound、読み筋と探索局面を渡す。nodes と nps は読み筋のない info を含め search_metrics で最新値を通知する。読み筋のない info は履歴行にしない。先読み中の info は、その予想手を適用した局面に対するもの。表示用に通常思考と区別し、読み筋の日本語変換にも予想局面を使う。予想が外れた探索の結果を、実際の指し手や棋譜コメントに混ぜない。

棋譜と指し手の評価には bestmove に一致する候補の評価値と読み筋を用いる。別行で届いた評価値と読み筋は同じ探索深さと MultiPV 番号で対応付け、複数候補の行が交互に届いても保持する。一致しない・曖昧な値は流用しない。理由なしの #DRAW は CSA 棋譜に %HIKIWAKE として記録する。

## Electron とアダプターの通信

アプリはアダプターを --app-mode で起動し、最初の標準入力行に設定を JSON で渡す。その後 q は終局待ちの終了予約、c は予約取消。標準出力は１行１イベントの JSON Lines で、state、game_started、move、search_state、analysis_update、analysis、game_ending、game_finished などを送る。棋譜保存先の通知は game_started より後になる場合がある。フィールドや順序を変更する場合は app/main.js の eventFor と連携テストも更新する。

終了予約は進行中の対局を切らない。強制終了は別操作であり、対局中は切断負けになる場合がある。標準入力が閉じた場合も無人のエンジンを残さないため、終局後に終了する。

アプリがマッチング確認に対応する場合、設定 JSON で `match_gate` を有効にする。アダプターは対局情報受信時に `match_found` を出し、main から `allow` を受けてから AGREE する。応答が10秒以内にない場合は安全のためエラー終了する。

アプリへの通知は別スレッドのキューで送る。出力の受信側が滞った際、対局状態や棋譜エラーなどの重要イベントを優先し、思考ログの途中情報は間引くことがある。出力先が閉じた場合は終了を予約し、対局中なら終局まで続ける。棋譜の書き込み・最終保存が失敗した場合は `record_error` で通知する。

エンジンの標準エラーはアダプターが読み取り、アプリが失われても読み続ける。CSA の作成・書き込みは対局通信とは別スレッドで順番に実行し、キューが上限に達した場合や終局後に保存が完了しない場合は不完全な棋譜として通知する。終局通知には最終手番の経過時間を含める。
